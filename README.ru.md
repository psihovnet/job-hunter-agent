# job-hunter-agent

[English](README.md) · **Русский**

Персональный Telegram-бот, который следит за каналами с вакансиями вместо
тебя. Он читает только те Telegram-каналы, которые ты сам добавил, отбирает
посты по твоим ключевым и стоп-словам и присылает подходящие вакансии тебе в
личку. Каналы и ключевые слова меняются прямо в боте командами — без правки
конфигов и перезапусков.

## Зачем

Искать работу через Telegram — значит каждый день листать десятки каналов, где
большая часть постов не про тебя. Бот листает за тебя: проверяет каналы по
расписанию, оставляет только то, что подходит, и никогда не присылает одну и
ту же вакансию дважды.

## Возможности

- **Читает всё, что видит твой аккаунт** — публичные каналы, закрытые (платные)
  каналы, на которые ты подписан, и даже ботов, присылающих вакансии в личку.
  Работает через пользовательский Telegram API (Telethon) только на чтение.
- **Гибкий поиск по словам** — без учёта регистра и целыми словами, звёздочка
  вместо окончания (`разработ*` → разработчик, разработка), фразы из
  нескольких слов и стоп-слова, отбрасывающие пост целиком (`junior`, `стажёр`).
  Одинаково работает с кириллицей и латиницей.
- **Готовые группы каналов** — `/groups` показывает кнопки с подборками
  («Россия и СНГ» / «Зарубежные»; IT и продукт, финтех и банки, геймдев),
  которые подключаются и отключаются одним нажатием.
- **Дедупликация** — каждый отправленный пост сохраняется в SQLite; ссылки
  нормализуются (без трекинг-параметров), так что вакансия, перепощенная с
  `?utm=...`, повторно не придёт.
- **Полное управление из чата** — добавление/удаление каналов и слов, поиск по
  запросу, пауза расписания, статистика за сутки.
- **Доступ только владельцу** — бот отвечает только указанному `chat_id`.
- **Безопасность по умолчанию** — токен бота не попадает в логи, секреты
  исключены из Docker-образа, логи ротируются.
- **Деплой одной командой** — Docker Compose с volume для конфигов, сессии,
  базы и логов.

## Как это работает

```
 ┌──────────────┐   Telethon (user API)   ┌────────────────────┐
 │  Telegram-   │ ──────────────────────▶ │ sources/           │
 │  каналы и    │                         │ telegram_channels  │
 │  боты        │                         └─────────┬──────────┘
 └──────────────┘                                   │ посты
                                                    ▼
 ┌──────────────┐   слова / каналы        ┌────────────────────┐
 │  Ты          │ ◀─────────────────────▶ │ bot/ (команды,     │
 │  в Telegram  │   команды через Bot API │ планировщик)       │
 └──────▲───────┘                         └─────────┬──────────┘
        │                                           ▼
        │                                 ┌────────────────────┐
        │   новые подходящие вакансии     │ core/matcher  →    │
        └──────────────────────────────── │ core/state (SQLite)│
                                          │ → core/notifier    │
                                          └────────────────────┘
```

Один asyncio-процесс поднимает и бота (python-telegram-bot), и периодическую
задачу поиска (через его `JobQueue`). Каждый цикл читает свежие сообщения из
каналов, прогоняет их через фильтр, сверяется с SQLite и отправляет новое.
Ручной и плановый поиск используют общий lock, поэтому никогда не обращаются к
сессии Telethon одновременно.

## Стек

- Python 3.11, asyncio
- [python-telegram-bot](https://python-telegram-bot.org/) 21 — команды, inline-кнопки, планировщик
- [Telethon](https://docs.telethon.dev/) — чтение каналов через пользовательский Telegram API
- Pydantic 2 — валидация JSON-конфигов
- SQLite — дедупликация и статистика
- Docker / Docker Compose

## Структура проекта

```
main.py                    точка входа: бот + планировщик
orchestrator.py            один цикл поиска: чтение → фильтр → дедуп → отправка
bot/bot_commands.py        команды, доступ только владельцу, расписание
bot/groups.py              готовые группы каналов с кнопками
core/matcher.py            поиск по ключевым словам, звёздочкам, стоп-словам
core/state.py              дедупликация в SQLite
core/notifier.py           отправка вакансий владельцу
core/storage.py            хранение JSON-конфигов
core/config_schema.py      Pydantic-модели
sources/telegram_channels.py   чтение каналов через Telethon
sources/login_telethon.py      разовый интерактивный вход
config/channel_groups.json     списки каналов для групп
```

## Запуск

### 1. Установка зависимостей

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

### 2. Значения для `.env`

| Переменная | Где взять |
|---|---|
| `TELEGRAM_BOT_TOKEN` | В Telegram написать `@BotFather` → `/newbot` → скопировать токен |
| `TELEGRAM_CHAT_ID` | Написать своему боту любое сообщение, затем открыть `https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getUpdates` — взять `chat.id`. Только этот chat_id сможет управлять ботом (остальным бот не отвечает) |
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` | https://my.telegram.org → API development tools (нужны, чтобы читать Telegram-каналы через свой аккаунт) |
| `POLL_INTERVAL_MINUTES` | Как часто проверять каналы, по умолчанию 60 |
| `TG_CHANNEL_LOOKBACK_HOURS` | За сколько часов назад читать сообщения каналов, по умолчанию 24 |

### 3. Вход в Telegram (один раз)

Прежде чем бот сможет читать каналы, нужно **один раз, вручную, локально**
(не через `docker-compose up -d`) войти в Telegram как обычный пользователь —
это создаёт файл сессии, который дальше используется без повторного входа:

```bash
python -m sources.login_telethon
```

Скрипт спросит номер телефона, код из смс (и пароль 2FA, если он у тебя
включён), после чего создаст `config/telethon_session.session`.

Канал должен быть публичным (есть @username) или аккаунт, под которым сделан
вход, должен быть на него подписан.

Один цикл поиска можно прогнать вручную, без запуска бота (найденные посты
попадут в лог, а не в Telegram):

```bash
python -m orchestrator
```

### 4. Деплой на VPS через Docker

```bash
git clone https://github.com/psihovnet/job-hunter-agent.git
cd job-hunter-agent
cp .env.example .env
# заполнить .env (раздел 2)
python -m sources.login_telethon   # один раз, вручную, до docker-compose up
touch state.db job-hunter.log      # иначе Docker создаст на их месте папки
docker-compose up -d
```

`./config` (ключевые слова, список каналов, telethon-сессия, флаг паузы),
`state.db` и `job-hunter.log` смонтированы как volume — они переживают
пересоздание контейнера.

Логи:

```bash
docker-compose logs -f
```

## Команды бота

**Группы каналов**

- `/groups` — кнопки с готовыми подборками: «Россия и СНГ» и «Зарубежные»,
  внутри по сферам (IT и продукт, финтех и банки, геймдев). Нажатие
  подключает или отключает группу целиком. Состав групп лежит в
  `config/channel_groups.json`, его можно править руками.

**Каналы**

- `/add_channel @channel1 @channel2` — добавить (можно ссылкой `t.me/channel`)
- `/my_channels [поиск]` — каналы и группы, в которых состоит твой аккаунт,
  с готовой командой добавления; так находятся закрытые (платные) каналы 🔒
- `/add_channel 1234567890` — добавить закрытый канал по id (или ссылкой на
  пост из него `t.me/c/1234567890/55`). Бот читает его через твой аккаунт,
  поэтому подписка должна быть активна
- `/add_channel @somebot` — бота, который присылает тебе вакансии в личку,
  добавляют так же: бот читает его сообщения в вашем чате (🤖 в списках)
- `/remove_channel @channel1` или `/remove_channel 1234567890`
- `/list_channels`

**Ключевые слова** (несколько — через запятую)

- `/keywords` — показать текущие
- `/add_keyword python, team lead, разработ*` — пост приходит, если в нём есть
  хотя бы одно из этих слов
- `/remove_keyword python`
- `/add_exclude junior, стажёр` — пост отбрасывается, если есть любое из них
- `/remove_exclude junior`

Как ищутся слова: без учёта регистра и целиком (`java` не найдёт
`javascript`). Звёздочка заменяет любое окончание: `разработ*` найдёт
«разработчик», «разработчика», «разработка». Фразы тоже работают, звёздочка —
в любом слове: `руководител* проект*` найдёт «руководителя проектов». Если
список слов для поиска пуст — приходят все посты из каналов.

**Управление**

- `/search_now` — проверить каналы прямо сейчас
- `/pause`, `/resume` — приостановить/возобновить плановые проверки
- `/stats` — сколько вакансий отправлено за последние 24 часа
